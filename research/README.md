# 真实试用：收集与证据边界

当前尚未收到本人授权公开、可追溯到真实试用者的反馈记录。准备好问卷不能算用户验证完成。

已知需求来自项目发起人的开发要求：平台主动评估候选、帮助量化投入、协商具体服务比例。这是发起人需求，不是独立学生访谈或可用性验证。

目标收集2–3位实际参与者，区分发起人／团队与目标使用者。同一人切换多个演示身份仍只是一位，自动化不计入研究。

## 十分钟任务

1. 描述最近一次真实求助／技能交换、原来怎么选人和谈条件，以及困难。
2. 比较三名候选的能力、工时、总价，说明选择理由。
3. 比较60↔90，填写收到服务的价值，可以不同意平台。
4. 第一项验收后退出，解释仍欠谁什么、何时能关闭订单。
5. 运行无证据和无交集案例，解释下一步。
6. 填写帮助、阻碍、下次是否愿意使用，并选择是否同意匿名公开。

`/study`提供任务与匿名表单，回馈仅下载至本人设备，不传后台。本人决定是否交给团队；未同意的原文、身份及第三人信息不得公开。

## 如何记录

匿名A／B／C，记录参与者类型、收集方式、本人是否实际操作、公开同意、真实事例、原流程、帮助、阻碍及再使用意愿。发起人转述标为转述／自报，不能称为现场观察。

保留负面反馈和误解，不按预设结论改写。少量反馈只能支持初步质性线索，不能推断普遍需求、成交率或定价准确性。

原始材料放排除Git的`research/private/`，公开前检查匿名与授权。`consented-feedback.json`只保存实际提供且授权公开的反馈，当前为空。真实反馈到达后才更新结论及Deck，不能由AI生成参与者和引语。
